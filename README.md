# will

will 是一门系统编程语言：**像 C 一样快，像 Python 一样好写，不用 unsafe 也安全**。
它经 `willc` 编译到 LLVM —— `willc` 是**程序的一种文本形态，不属于任何语言**：人、脚本、AI 都能读它、diff 它、检查它，从而看懂编译器到底理解了什么。

## 它是什么

- **C 是一等公民**。C 函数与本语言函数一样声明、调用、链接；调用点就是那次调用，**零额外指令**。
- **一切显式，没有隐式**。没有隐式转换、隐式拷贝、隐式所有权、隐式阻塞；每一处转换、移动、释放都写在源里。
- **内存由显式智能指针管理，编译期检查**。没有区域模型，没有 `unsafe`：单个对象释放 **O(1)**，成组释放也 **O(1)**，而且运行期不会出现编译期没说过的内存错误。
- **并发是无栈的**。协程是 `willc` 上的状态机，不是一段栈：不切栈、不碰栈界、不手写展开信息。
- **IO 全在运行时**，以原生、带类型的操作暴露；运行时**移植** C 实现，而不是调用某个 C 库，所以程序不依赖机器上装了什么。
- **包与增量缓存走 Go 那一套**：一个目录一个包，缓存键包含每一步**真正读过**的一切 —— 包括它解析过的 C 头。

## 硬指标（要量，不要声称）

| 项 | 目标 |
| --- | --- |
| 计算 | 同一份内核，达到 C 的 **≥95%** |
| 内存管理 | 达到 C 分配器的 **≥95%** |
| 尾延迟 | **C++ 级别** |
| 对 Rust | 同一内核上**不低于**它 |
| 内存安全 | 编译**错误**或**警告**，绝不留给运行期 |

## 文档在哪

- `desc/` —— **唯一规范来源，不进 git**（由 `.gitignore` 排除）。按类型拆分：
  - `desc/语言/` —— 语言本身：总览、语法、语义、内存、并发、C 互操作、运行时与 IO、工具链、性能、诊断。
  - `desc/经验/` —— 造过一门同形状语言（zyx）得到的东西，**故意带过来**：编译器、代码生成、运行时、缓存与构建、工程流程、平台事实。
- 改规范只改 `desc/`；代码里的注释不复述规范，只在实现选择需要解释的地方说清为什么。

## 项目规矩

- 代码（标识符、字符串、注释、提交信息）一律英语；文档可以中文；源文件只含 ASCII。
- 一项一提交；提交信息写清**为什么**。
- 每个诊断都要有**断言报文文本**的测试，只比错误码不够。
- 记录（golden 文件、覆盖面清单）**就是测试**：它随改动同一次提交一起动。
- 不写占位实现；不发明特性：文档里没有的先停下并报告。
